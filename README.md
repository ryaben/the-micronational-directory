# the-micronational-directory
Community-oriented platform for registering micronations

## AI entry assistant

The new-entry form uses AI to suggest values from source material and to provide preliminary criteria reviews for submitted GitHub Issues. The result is triage guidance only: moderators still approve or reject submissions through the existing moderation flow.

## Local MicroWiki research

The source-research workflow reads local datasets from `src/assets/sources/`: MicroWiki, Micronaciones Fandom, MicrasWiki, and Google My Maps. Choose one with `CANDIDATE_SOURCE` (`microwiki`, `micronaciones_fandom`, `micraswiki`, or `google_mymaps`). For example in Git Bash: `CANDIDATE_SOURCE=microwiki CANDIDATE_OFFSET=0 MAX_ENTRIES=1 node scripts/ingest-micronation-sources.mjs`. Increase the zero-based `CANDIDATE_OFFSET` to process later portions of the selected dataset. You can optionally set `CANDIDATE_NAMES` to newline-separated names; only exact local name matches are used. MicroWiki and Micronaciones Fandom article links are formed from their MediaWiki page IDs, while MicrasWiki article URLs are read from each record's `websites` field. Google My Maps records contribute names, descriptions and coordinates, with the map itself treated only as a discovery source. These local scrapes may be partial or stale; Groq still researches each candidate and supplies evidence before an Issue can be created. The script reads Groq and GitHub credentials from `.env` locally. For GitHub Actions, add `GROQ_API_KEY` as a repository secret and use **Actions → Research micronations from local sources → Run workflow**, choose `candidate_source`, set `candidate_offset`, and set a limit from 1 to 5. It checks existing directory names and open micronation issues, looks up Wayback snapshots for source URLs, and creates issues through the same GitHub issue service used by the submission form. It never writes to public JSON files or applies the approval label.

Generated suggestions include field-level evidence and uncertainty markers. Review all fields, sources, duplicates, activity, and eligibility before approval. Wayback lookup uses the Internet Archive CDX index; a missing or unusable snapshot leaves the underlying fact unverified. Field rules are shared with the form tooltips in `src/assets/entry-field-guidance.json`.

For local development, add `GROQ_API_KEY=...` and `GEMINI_API_KEY=...` to `.env` or `.env.local`, then restart `npm run dev`; Vite serves the AI endpoints locally. The AI filter uses Groq's multimodal `qwen/qwen3.8-27b` model for both text and flag-image filtering. To meter its use separately, create a Groq key in a separate project and set the optional server-only `AI_FILTER_GROQ_API_KEY`; otherwise it falls back to `GROQ_API_KEY`. Pasted text extraction and submission review also use `qwen/qwen3.8-27b`; URL extraction uses Groq browser search (`openai/gpt-oss-20b`); image/PDF extraction uses Gemini. Enable the needed models in each Groq project. For deployment, set the keys in Vercel's server-side Environment Variables. Do not use a `VITE_` prefix. Check each provider's current limits and data terms before handling sensitive source material: [Groq rate limits](https://console.groq.com/docs/rate-limits) and [Google AI pricing](https://ai.google.dev/gemini-api/docs/pricing). The assistant accepts PNG, JPEG, WebP, and PDF files up to 3 MB, or pasted text up to 12,000 characters.
